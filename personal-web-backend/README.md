# Personal Virtual Assistant — Backend

AWS serverless backend for the `personal-web` frontend. Two independently deployable Lambdas:

```
personal-web-backend/
├── template.yaml          # AWS SAM: both functions, HTTP API, Function URL, IAM
├── samconfig.toml         # SAM deploy defaults (region us-east-2, stack name)
├── api-lambda/            # HTTP API Lambda  → /config, /suggestions, feedback endpoints
│   ├── index.js
│   └── package.json
└── streaming-lambda/      # Function URL Lambda (RESPONSE_STREAM) → Bedrock AgentCore relay
    ├── index.js
    └── package.json
```

- **api-lambda** sits behind an **API Gateway HTTP API** and serves `GET /config`, `GET /suggestions`, `POST /sessions/{sessionId}/feedback`, `POST /sessions/{sessionId}/messages/feedback`.
- **streaming-lambda** is exposed via a **Lambda Function URL** with `InvokeMode=RESPONSE_STREAM`; it invokes a Bedrock AgentCore runtime and streams NDJSON tokens to the browser.
- All data is persisted in **DynamoDB** (tables created via the console — see `DEPLOYMENT.md`).

The session id is generated by the **frontend**; the backend only consumes it (upsert-by-id) and never overrides the client-computed session duration.

**Docs:**
- [`DEPLOYMENT.md`](./DEPLOYMENT.md) — full setup, deploy, seeding and testing steps.
- [`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md) — how each Lambda works: handlers, event/response shapes, env vars, IAM, data model, local testing, and how to extend.

Runtime: **Node.js 22 (`nodejs22.x`)**, arm64.
